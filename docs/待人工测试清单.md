## 阻塞项（必须先做，否则后面全都测不了）

### B1. 重启 BlueStacks 模拟器

**为什么卡住**：在反复安装/卸载 APK 的过程中，模拟器的 `system_server` 崩溃了。`service check package` 返回 `not found`，44 个残留服务，安装直接报 `Can't find service: package`。我从命令行执行了 `setprop ctl.restart zygote`，它短暂恢复过一次，随后又崩了。**这台 BlueStacks 实例需要你在图形界面里手动重启**（关掉 BlueStacks 窗口再打开，或从菜单选「重启实例」）。

**怎么确认已恢复**：

```bash
source scripts/android-env.sh
adb devices                                  # 应看到 127.0.0.1:5555  device
adb -s 127.0.0.1:5555 shell "service check package"   # 必须返回 "Service package: found"
adb -s 127.0.0.1:5555 shell "service check activity"  # 同上
```

**通过标准**：两条都返回 `found`。只要还是 `not found`，任何安装都会失败，不要继续往下测。

### B2. macOS 首次授权（系统音频录制）

**为什么卡住**：macOS 的 TCC 权限弹窗**只在有 GUI 会话的进程里出现**。我用命令行直接跑采集助手，`AudioDeviceCreateIOProcID` 会一直阻塞等待那个永远不会出现的授权窗口——我加了看门狗确认了这一点，日志停在「创建 IOProc…」之后。

**怎么测**：

1. 双击打开 `target/release/bundle/macos/Kanami.app`
2. 切到「发送」页，点「开始发送」
3. 系统应弹出「Kanami 想要录制系统音频」→ 点「允许」
4. 如果没弹窗或点了拒绝：**系统设置 → 隐私与安全性 → 麦克风**（以及「屏幕录制」）里手动勾上 Kanami
5. 完全退出应用再重开

**通过标准**：
- 播放任意音乐，Kanami 日志里出现 `[采集] INFO: 开始采集`
- 应用内「已发送帧」数字持续增长
- 若 6 秒无数据，日志会出现提示「通常是缺少音频录制权限」

**已知限制**：不授权时不会崩溃，只是静音发送。这是有意的降级设计。

## 桌面端（macOS 本机）

### D1. 三档模式的实际延迟差异

**怎么测**：分别用三档模式，Mac A 发 → Mac B 收（或本机回环），播放节拍器音频，同时用另一台设备录制声音，比对音画同步。

**通过标准**：
| 模式 | 缓冲区（应用内显示） | 预期端到端 |
|---|---|---|
| 低延迟 | 固定 20ms，不增长 | 60–80ms |
| 标准 | 40–120ms 自适应 | 120–150ms |
| 高音质 | 60–200ms 自适应 | 180ms 左右 |

「缓冲」数字在界面上直接可见。低延迟档如果自己涨到 20ms 以上，就是 bug。

### D2. 一播放端接多音源（混音台）

**怎么测**：两台 Mac 都开 Kanami 当音源，第三台当播放端，三台连同一个 Wi-Fi。播放端依次连接两个音源。

**通过标准**：
- 两路声音同时出声，不互相打断
- 每路的音量滑杆、静音开关、独奏按钮都生效
- 拔掉其中一台的网络，另一台的声音**不受影响**（只该路变成灰点）
- 同时接 4 路时，声音不爆音、不卡顿

### D3. 本机同时收发的回授

**怎么测**：Mac A 发给 Mac B，同时 Mac B 也发给 Mac A，两边的喇叭都开着。

**通过标准**：**不应该出现啸叫或回声**。macOS 上采集会排除本进程，理论上断掉了回路。如果出现啸叫，说明进程排除没生效，把 `KANAMI_LOG=/tmp/cap.log` 设上重跑，日志里应有「已解析本进程音频对象 id=…，将从采集中排除」。

### D4. 局域网自动发现

**怎么测**：两台设备装好 Kanami，连同一个 Wi-Fi，打开应用等 10 秒。

**通过标准**：
- 双方设备列表里互相出现，间隔不超过 5 秒
- 关掉一台，另一台约 8 秒后它从列表消失
- 点「扫描」能立即刷新

**已知限制**：公司/学校 Wi-Fi 常开 AP 隔离，mDNS 和广播都会失效。这时用「手动添加」填 `IP:47822`。

### D5. 托盘行为

**怎么测**：点窗口右上角关闭按钮。

**通过标准**：窗口消失但进程还在，菜单栏有 Kanami 图标；托盘菜单能「显示主窗口」「开始/停止发送」「退出」。

### D6. 输出设备切换

**怎么测**：设置页选不同输出设备（内建扬声器 ↔ 蓝牙耳机）。

**通过标准**：切换后声音从新设备出来。默认输出是 44.1kHz 蓝牙耳机时，48kHz 的重采样路径必须没杂音。

### D7. 接入授权

**怎么测**：Mac B 首次连 Mac A 时。

**通过标准**：Mac A 弹出「有设备请求接入」，点「允许」后连接成功；再连第二次不再询问。点「拒绝」则 B 那边看到失败提示。

## Android 端

### A1. 应用到设备安装

```bash
source scripts/android-env.sh
adb -s 127.0.0.1:5555 install -r src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release-unsigned.apk
```

**注意**：release APK 是**未签名**的。先用 keystore 签名再装：

```bash
$JAVA_HOME/bin/keytool -genkeypair -keystore /tmp/kanami.keystore -alias kanami \
  -storepass kanami123 -keypass kanami123 -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=Kanami"
"$ANDROID_HOME/build-tools/36.0.0/apksigner" sign --ks /tmp/kanami.keystore \
  --ks-pass pass:kanami123 --key-pass pass:kanami123 \
  --out /tmp/kanami-signed.apk src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release-unsigned.apk
adb install -r /tmp/kanami-signed.apk
```

### A2. 界面能正常渲染

**为什么没测成**：debug APK 的 `devUrl` 指向 `http://localhost:1420`，设备上访问不到，所以白屏。release APK 里前端资源确认已打进 `libkanami_ai.so`（`strings` 能看到 `/assets/index-*.js`），但还没能装上验证。

**怎么测**：装上 release APK 后打开应用。

**通过标准**：
- **不是白屏**，能看到「发送 / 接收 / 设置」三个底部 Tab
- 顶部显示设备名
- 界面是移动端布局（antd-mobile），不是把桌面版硬塞进小屏

### A3. Android 作为接收端

**怎么测**：Mac 当音源，手机连上来。

**关键前提**：BlueStacks 是 QEMU NAT，客体的地址是 `10.0.2.15`，**Mac 无法主动连到它**。所以必须让 Android 先发起：

1. Mac 上「设置」页记下局域网地址（如 `192.168.31.45`）和信令端口
2. Android 上「接收」页 → 手动添加 → 填 `192.168.31.45:<信令端口>`
3. 点「连接」

**通过标准**：手机上能听到 Mac 放的歌。**注意不要用 127.0.0.1 或 adb reverse**，那样等于没走网络路径。

### A4. 麦克风上行

**怎么测**：Android 当音源，Mac 当播放端。Android 上「发送」页选麦克风，点开始；Mac 上手动添加 Android 的地址并连接。

**通过标准**：对着手机说话，Mac 喇叭里能听到。

**已知限制**：Android 的系统声音采集（AudioPlaybackCapture）在 BlueStacks 上**物理上不可用**——实测 `r_submix` Handle=0、HAL 库全盘不存在、AudioFlinger 无 record 线程。代码里已按麦克风路径实现，并在能力探测里如实报告。

### A5. 锁屏后继续播放

**怎么测**：Android 接收时锁屏，等 1 分钟。

**通过标准**：锁屏后声音不断。

**已知限制**：需要前台服务 + 通知权限，代码里已声明权限，但前台服务的 Java 侧实现还**没有接**。这条大概率**会失败**，需要补 Android 端的 Service。

同上，走 `打包 / ubuntu-22.04`。

### C3. Windows 的 WASAPI loopback 采集

**怎么测**：Windows 上开 Kanami 发送，播音乐。

**通过标准**：能抓到系统声音。Win11 22H2+ 应该支持排除本进程；Win10 会降级并在 UI 提示「建议戴耳机」。

### C4. Linux 的 monitor source 采集

**怎么测**：Linux 上确认 `pactl list short sources` 里有 monitor，然后开 Kanami 发送。

**通过标准**：音源下拉里能看到 monitor 设备，选中后能出声。

### C5. iOS

**当前状态**：完全没做。本机无 Xcode、无 iphoneos SDK、无签名身份，一行都编不了。

**要做的事**：装 Xcode → 加开发者账号 → `pnpm tauri ios init` → 补 `Info.plist` 的 `NSLocalNetworkUsageDescription` 与 `NSBonjourServices` → 补 `UIBackgroundModes: audio`。
