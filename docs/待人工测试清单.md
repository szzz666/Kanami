## 快速验收（约 15 分钟）

只想确认核心功能可用，做这四步就够。

### 第 1 步：Mac 当音源 → Android 当播放端

**在 Mac 上**
1. 打开 `Kanami.app`
2. 音源选「系统声音（推荐）」
3. 点「开始发送」
4. 若系统弹出权限请求（屏幕录制 / 麦克风），**点允许后重启应用**

**在 Android 上**
1. 打开 Kanami，进「接收」页
2. 点刷新按钮
3. Mac 会出现在设备列表，点「连接」

**在 Mac 上**：弹出「有设备请求接入」→ 点「允许」

**通过标准**
- [ ] Mac 上出现「有设备请求接入」卡片
- [ ] 点允许后 Android 显示「正在接收 1 路」
- [ ] Mac 放音乐时手机能听到声音
- [ ] Android 混音台显示「缓冲 XXXms」（不是 0）

### 第 2 步：Android 当音源 → Mac 当播放端

反过来做一遍：
1. Android 点「开始发送」，音源选「麦克风」
2. Mac 进「接收」页 → 刷新 → 找到 Android → 连接
3. Android 点「允许」

**通过标准**
- [ ] Mac 混音台出现 Android
- [ ] 对着手机说话，Mac 能听到

### 第 3 步：三档模式

在播放端切档位，观察混音台里的缓冲数字。

**通过标准**
- [ ] 缓冲随档位变化（标准 40–120ms / 低延迟 20ms / 高音质 60–200ms）
- [ ] 三档听感有差异：低延迟更跟手，高音质更饱满

### 第 4 步：一播放端接多音源

两台音源都点「开始发送」，播放端分别连上。

**通过标准**
- [ ] 混音台显示「2/8」或更多
- [ ] 两路声音同时能听到
- [ ] 调某一路音量/静音，只影响那一路
- [ ] 点「独奏」其它路闭嘴，再点一次恢复

### 第 5 步：一音源推给多播放端

反过来做：**一台音源，两台播放端同时听**。

1. 音源端（比如手机）点「开始发送」
2. 播放端 A（比如 Mac）连上，并在音源端点「允许」
3. 保持 A 的连接，播放端 B（比如另一台电脑）也连上并允许

**通过标准**
- [ ] A 在 B 接入后**仍然有声音**（这是关键：早期版本 B 一接入，A 就静默断流）
- [ ] B 也有声音
- [ ] 两端听到的内容一致

> 已实测验证（Redmi Turbo 5 Max 作音源，两个 Mac 客户端）：
> A 全程 18 秒收到 753 包、B 中途接入收到 418 包，两者都没有断流。

## Android 专项

### A1. 系统声音采集

**前提**：Android 11+（API 30+）。实测机型 Redmi Turbo 5 Max / Android 17。

1. 音源选「系统声音」
2. 点「开始发送」
3. 系统弹出「要开始使用Kanami录制或投放吗？」
4. **在「应用范围」一栏点一下，选「共享整个屏幕」**
5. 点「下一步」

**通过标准**
- [ ] 通知栏出现「Kanami 正在发送系统声音」
- [ ] 用别的 App 放音乐时对方能听到

> **这是最容易踩坑的一步。** 默认是「共享一个应用」，选它只能抓那一个 App 的声音，
> 而且 Kanami 自己会被排除。选错的表现是「显示正在发送但对方听不到」。

### A2. 锁屏保活

1. 建立一条接收连接
2. 按电源键锁屏，等 3 分钟
3. 解锁

**通过标准**
- [ ] 锁屏期间声音不断
- [ ] 解锁后仍在接收

**不通过时**：到「设置 → 应用管理 → Kanami → 电池」设为「无限制」，
并把 Kanami 加入厂商的自启动白名单。

### A3. 开机自启

1. 建立一条连接（保持发送或接收）
2. 重启手机
3. 等开机完成，**不要手动打开 Kanami**

**通过标准**
- [ ] 通知栏自动出现 Kanami 的通知

> 只有重启前有活跃会话时才恢复。上次主动停止的话重启不会启动——
> 这是刻意的，避免在用户不知情时打开麦克风。

### A4. 进程被回收后自动恢复

1. 点「开始发送」
2. 到「设置 → 应用」强制停止 Kanami
3. 重新打开

**通过标准**
- [ ] 界面直接显示「正在发送」，不用重新点按钮
- [ ] 日志里有「已恢复上次的发送」

## 桌面端专项

### D1. macOS 权限

首次用系统声音采集需要「屏幕录制」权限：
- 系统设置 → 隐私与安全性 → 屏幕录制 → 勾选 Kanami
- **授权后必须重启应用才生效**

**通过标准**
- [ ] 授权并重启后点「开始发送」能采到声音
- [ ] 未授权时日志会出现「采集 6 秒无数据：通常是缺少音频录制权限」

### D2. 托盘行为

点窗口关闭按钮。

**通过标准**
- [ ] 窗口消失但应用仍在运行（菜单栏有图标）
- [ ] 点菜单栏图标能重新打开
- [ ] 托盘菜单能开始/停止发送

### D3. 输出设备切换

有多个音频输出时（外接声卡、蓝牙耳机）：
1. 在设置里切换输出设备
2. 断开重连一次

**通过标准**
- [ ] 声音从新选的设备出来

## 排查手册

### 「显示正在发送，但对方没有声音」

按顺序检查：
1. **播放端连上了吗？** 看播放端混音台是否出现这一路
2. **音源端授权了吗？** 播放端首次连接需要音源端点「允许」
3. **Android 系统声音选的是「整个屏幕」吗？**（见 A1）
4. **macOS 授权屏幕录制了吗？**（见 D1）

### 「设备列表是空的」

1. 确认两台设备在**同一个 WiFi 网段**（不要一个 5G 一个 2.4G 的不同网段）
2. 检查路由器是否开了「AP 隔离」（会阻断设备间通信）
3. 用「手动添加」直接填对方 IP:端口

### 「延迟一直是同步中」

端到端延迟需要时钟同步，通常连接后几秒内完成。
一直不同步的话检查两台设备间是否有防火墙拦截 UDP。
这只是显示问题，不影响声音传输。

### 看日志

- **Android**：`adb logcat | grep RustStdoutStderr`
- **macOS / Linux**：终端里运行应用，日志直接输出
- **Windows**：PowerShell 里运行 `.exe`
